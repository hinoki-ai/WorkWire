## Mission 1 — real synchronization

Replace the current scan-and-copy ceiling with a content-aware engine while preserving existing two-PC behavior.

Required power:

1. Multiple sync folders and multiple peers. A folder explicitly selects peers; there is no global all-to-all assumption.
2. Folder modes: send-receive, send-only, receive-only, and archive-only.
3. Include/exclude rules with deterministic matching, comments, negation, directory rules, and testable explanations for why a path was included or ignored.
4. Native change observation where available plus a durable change journal. Always retain a correctness-first scan fallback after overflow, missed events, restart, or unsupported filesystems.
5. Lazy content hashing. Reuse cached hashes only when the file identity proves they remain valid; never treat equal size/mtime as final content equality.
6. Deterministic chunk manifests for large files. Transfer only missing chunks when the remote has matching regions.
7. Resumable ordinary file and chunk transfers with durable offsets, temp-file isolation, final content verification, and atomic destination replacement.
8. Parallel transfer scheduling with configurable concurrency, priority, backpressure, pause/resume, bandwidth ceiling, and fair progress across files.
9. File version history before overwrite or delete, with retention, browsing, exact restore, and optional injected P1 vault storage.
10. Conflict records that preserve both contents, base observations, machine identities, timestamps, and resolution state. Support keep-left, keep-right, keep-both, and operator-supplied merged content.
11. Preserve sparse files when the platform exposes sparse ranges.
12. Continue ignoring symlinks by default, but make symlink policy explicit per folder: ignore, preserve-link, or follow-within-root. Never permit an accidental root escape.
13. Surface actual convergence state: scanning, hashing, transferring, paused, offline, conflict, out-of-space, error, and in-sync.
14. Protocol negotiation must allow compatible engine versions rather than requiring identical application bytes for every ordinary sync operation.
15. Existing manual copy/move, trash, local explorer, and current mirror behavior must keep working.

Do not implement compression unless benchmarks show it wins on realistic LAN data. Do not add a generic distributed database. Direct peer exchange is the product.

## Mission 2 — managed imaging and deployment

Turn raw image commands into a real image system.

Required power:

1. Image catalog records source machine, disk identity, geometry, partition table, filesystems, boot mode, creation tool, compression, chunks, hashes, logical size, stored size, creation time, labels, and verification state.
2. Capture raw devices, ordinary image files, and sparse sources through an injected executor. Default tests use generated sparse files only.
3. Stream capture through optional compression and chunk/object storage without buffering whole images.
4. Resume interrupted capture and restore at verified chunk boundaries.
5. Restore to an explicitly resolved target and verify written samples or full content as configured.
6. Inspect an image without restoring it: manifest, partition layout, hashes, contained filesystems, and compatibility facts when native tools are available.
7. Pin, clone, rename, search, export, import, verify, and explicitly delete catalog images.
8. Build deployment plans for one or many machines with source image, target-disk resolution, preflight facts, execution steps, concurrency, post-restore operations, and verification.
9. Support rollout modes: all-at-once, bounded parallel, canary-then-rest, and stop-on-first-failure. P3 executes fleet jobs; your engine owns the deterministic plan and result aggregation.
10. Provide peer-assisted chunk distribution so machines that already hold verified chunks can seed peers on the LAN. Do not build a new general P2P network stack.
11. Support unattended-install and post-image bundles as ordered file-plus-command manifests. Keep them transparent and editable; do not invent a package manager.
12. Emit machine-readable reports comparing intended versus observed image/deployment results.

## Mission 3 — priority salvage

Build an engine designed for a failing source where every extra read matters.

Required power:

1. Inventory a readable directory tree or mounted recovered filesystem without opening every file during discovery.
2. Build a priority queue by operator rules: explicit paths first, documents, source/code, credentials/configuration, small unique files, photos/media, then everything else.
3. Estimate destination capacity and report what can fit at each priority level.
4. Copy with durable per-file checkpoints, hashes, retry counts, read errors, partial status, and exact destination mapping.
5. Resume after process death without recopying verified files.
6. Allow multiple healthy destinations and spill priorities across them deterministically.
7. Produce checksum manifests and a final recovered/missing/partial/corrupt report.
8. Offer metadata and small-file preview streams for UI consumption without loading large files into memory.
9. Detect duplicate content and avoid wasting destination space when enabled.
10. Never mutate the source in salvage mode.
11. Integrate with a ddrescue mapfile as an optional source-readability hint, but do not require ddrescue for ordinary filesystem salvage.
